# Short usability trial — unfilled worksheet

**Status: not yet conducted.** Recruit 3–5 classmates. Use anonymous participant codes; do not collect home/work addresses or screenshots showing private location. Test using an agreed public meeting point or a stop search. Participants may decline location access.

## Moderator script

“Please try these tasks and say what you expect each button to do. We are testing the interface, not you. I will avoid guiding you unless you get stuck. You can stop at any time.”

## Tasks and success criteria

1. **Find and identify a stop.** Search a named public stop or route, select the intended platform, then find its destination/direction. Success: the selected map/list stop and intended service match.
2. **Navigate to the stop.** From its map popup, choose walking navigation. Success: the map service opens with walking mode and the correct destination; the participant knows how to set/confirm the origin. Actual GPS and app switching should be checked on an Android phone.
3. **Save and understand a commute.** Save a label with chosen walking/buffer minutes; explain the recommended departure and expected arrival time. Success: the participant distinguishes departure advice from bus arrival time. If no live ETA exists, record this and assess understanding using a clearly labelled example; never report it as a live result.
4. **Change the time plan.** Edit both Usual and Extra time, save, switch plans and reopen the app. Success: both values persist and the active plan is understood.

Ask afterwards: “Which step was least clear?” and “What did you expect ‘walking directions’ and ‘bus services’ to do?” Do not ask leading questions such as “Is the new design better?”
